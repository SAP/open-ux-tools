FIX: Support Cloud Foundry adaptation projects across the UI automation flow.

- `read_odata_metadata_adp`: CF projects previously failed because the tool always built an ABAP service provider; it now detects CF projects and lists their OData data sources (with bound UI5 models) from the locally-built manifest, returning empty EDMX metadata since CF has no ABAP backend to proxy the `$metadata` request.
- `run_rta_workflow_step`: adds a `get_odata_metadata` step that fetches real OData `$metadata` (EDMX) for the given data-source URIs through the editor's authenticated browser session — the way to obtain real metadata for a CF project (where `read_odata_metadata_adp` returns empty EDMX). The fetch is pinned to the editor origin (an absolute/foreign-origin URI is refused) and classified by content type, so a lost-auth login page becomes a per-entry error rather than being returned as metadata. Large EDMX (over ~100 KB) is written to `<appPath>/webapp/.context/<name>-metadata.xml` and returned as a file path + byte size instead of inline, so a large service's metadata does not overflow the model.
- `run_rta_workflow_step`: the browser bridge reuses an authenticated session **per project**, keyed by `appPath`, so re-starting the same project reuses its login while a different project started on the same port (one editor stopped, the next opened) never inherits the previous project's cookies. ABAP projects skip session seeding entirely. Session reuse is in-memory within a process, with opt-in cross-restart persistence via `PLAYWRIGHT_SESSION_STATE_PATH` (stored with owner-only permissions). The `start`/`restart` steps return a structured `{ rtaStarted: false, needsUserAction: 'backend_login_required' }` signal instead of hanging/throwing when the editor URL serves a login page. Adds a `PLAYWRIGHT_HEADLESS` env toggle.
- `run_rta_workflow_step`: `appPath` is now a top-level step input, required for `start`, `restart` and `get_odata_metadata` (it identifies the project for session keying and is the save location for large metadata). The page registry is keyed by editor origin (one editor per origin; the full URL is kept on the handle for navigation). The `.context` write helper is shared with `read_odata_metadata_adp` rather than duplicated.
- `open_adaptation_editor`: detects CF via `isCFEnvironment` and allows a longer startup timeout for CF (the embedded approuter is slow to boot). The editor server is started the same way as ABAP without opening a browser (the `start` step opens it); when a CF project has no built `dist/` the tool fails fast with guidance to build first.
