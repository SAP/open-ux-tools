FEAT: ADP RTA automation over an opt-in HTTP relay in BAS Simple Browser, with Cloud Foundry support, without a server-side browser.

Enable with `SAP_FIORI_MCP_ADP_TOOLS=true`. The relay transport is selected automatically in BAS (`isAppStudio()`); set `SAP_FIORI_MCP_ADP_FORCE_AUTOOPEN=true` to exercise it locally. Playwright remains the transport for local and Cloud Foundry automation, so both coexist.

- `@sap-ux/adp-tooling` exposes an adaptation-project manifest builder API (`getMergedManifest`, `downloadAppResources`) for building the merged app descriptor and downloading base app resources via the project's `@ui5/task-adaptation` build, and ignores `.context`, `.session`, and `.adp` in the generated adaptation-project gitignore templates (CF and onPremise, kept identical).
- `@sap-ux/preview-middleware` owns the opt-in `/adp/api/rta/*` routes, relay state, and injected browser client, registered and injected only for adaptation previews whose editor child was given a valid 64-hex-character token privately by MCP; ordinary ADP previews and non-ADP previews are unchanged, so ADP tooling stays independent of the optional MCP automation. Requests authenticate with the `X-Relay-Token` header. The relay allows at most one pending/in-flight command and one owning browser document (`clientId`), rejecting conflicting polls, wrong-owner results, and duplicate completions; edits are never automatically replayed. `__reload__`/`__ready__` coordinate a fresh document, and `startRTA` adopts the editor's developer-mode UI adaptation instead of failing on a key-user permission error. An authenticated same-origin `__fetch__` command lets `get_odata_metadata` fetch EDMX through the editor page's browser context, so it works over the relay for Cloud Foundry adaptation projects in BAS. The client keeps polling when a result submission fails (the failed POST is logged, and a `__reload__` still reloads the page), targets the current window only when running inside a frame — in the top document a missing editor frame throws a clear "frame not found" error instead of silently targeting the parent — and serves its script from a value read once at module load, without per-request file-system access. The relay also carries the generic Unified Frontend Action family (`com.sap.ui.unified.frontend.actions.*`) behind the `describe_ui`/`execute_page_action` navigation steps, requiring `ActionHelpers` on the page and normalizing its raw results into the Flex `{ isSuccess, payload, error }` envelope so navigation works identically over the relay and Playwright.
- `@sap-ux/fiori-mcp-server` supports Cloud Foundry adaptation projects across the UI automation flow: `read_odata_metadata_adp` detects CF projects and lists their OData data sources from the built manifest (empty EDMX, as CF has no ABAP backend to proxy `$metadata`), and connects in BAS by resolving the ADP target via the shared `getAdpConfig` reader (passing the full `AbapTarget` including the BAS destination, and supporting the preview-middleware config in addition to `fiori-tools-preview`). `run_rta_workflow_step` adds a `get_odata_metadata` step that fetches real EDMX through the editor's authenticated session, reuses an authenticated session per project (keyed by `appPath`), waits for interactive login and the editor's `app-loaded` signal before starting RTA, and makes `appPath` required for `start`/`restart`/`get_odata_metadata`; `open_adaptation_editor` detects CF and allows a longer startup for the embedded approuter. Transient `startRTA` key-user permission failures are retried over the relay without reloading or replaying edits, and the generic modification workflow directs callers to the dedicated adaptation tools when it detects an adaptation project.

BUMP: `@sap-ux/fiori-tools-plugin` version is synced with `@sap-ux/fiori-mcp-server`.
