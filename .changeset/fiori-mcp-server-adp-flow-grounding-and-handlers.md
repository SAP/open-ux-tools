FEAT: Harden the ADP controller-extension flow so generated changes bind against real data instead of invented paths

- `adp-controller-extension-flow` skill: add a **grounding gate** — every binding path, entity type, entity set, and property name in an action payload or generated fragment/controller content must come from `get_context` (`contextEntityType`, `contextPath`, `availableModels`) or `read_odata_metadata_adp`, never from the control id, the user's phrasing, or a guess. `get_context` is now mandatory whenever a data binding is involved, with a matching binding-provenance rule at the payload-preparation step. This prevents the "button renders but the search/data never triggers" failure where `call_action` reports `success: true` yet the change does nothing.
- `adp_controller_extension` knowledge base: re-baseline all controller-extension and fragment namespaces on the descriptor variant **`id`** (surfaced verbatim as the namespace base) instead of the project folder name. The variant `id` already contains the `customer.` segment for `CUSTOMER_BASE` projects, so the previous "prepend `customer.` to the folder name" guidance was wrong wherever the folder name didn't happen to equal the id minus its prefix — it produced `extend()` namespaces, `.extension.*` handlers, and `Fragment.load` names that didn't match the generated `codeExt`/`addXML` change files, so extensions failed to load. Also add the `Fragment.load` `name` path pattern (`{variant-id}.changes.fragments.{Fragment}`), correct the owner-component note (no `runAsOwner` wrapper is needed inside a controller extension), and add a rule distinguishing event-handler resolution for view-embedded fragments (`.extension.{variant-id}.*` prefix) vs. dialog fragments loaded via `Fragment.load({ controller: this })` (bare method names), instructing always passing `controller: this`.
- `run_rta_workflow_step` playwright bridge: wait up to 60 s for the RTA frontend-action bridge to register before invoking it, then re-resolve the target frame, so early calls no longer fail while RTA is still starting.
