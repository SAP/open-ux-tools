# Troubleshooting

The data generator is optional. When its learned model, cache, or provider
cannot be used, the standard FE mockserver must remain available through its
built-in or deterministic generation path.

## Read the local diagnostics

Run the normal application command with debug logging enabled and look for
these stable local messages:

- `MOCK_DATA_GENERATOR_CAPABILITIES` reports whether the classifier and SFT
  tiers are ready, degraded, or unavailable.
- `MOCK_DATA_GENERATOR_SUMMARY` reports SHA-256 fingerprints, resource and row
  counts, SFT attempts, parsed responses, accepted and eligible slots, and the
  accepted-slot share.
- `MOCK_DATA_GENERATOR_TIMING` reports runtime initialization, whole-service,
  or generated-data-cache-hit duration.
- `GENERATED_DATA_CACHE_HIT`, `GENERATED_DATA_CACHE_MISS`,
  `GENERATED_DATA_CACHE_UNAVAILABLE`, and `GENERATED_DATA_CACHE_WRITE_FAILED`
  report local generated-snapshot cache state.

The summary never includes raw metadata, prompts, source rows, generated
values, runtime exception text, or model-cache paths. Only lowercase 64-digit
SHA-256 component fingerprints are logged; any other runtime-provided value is
reported as `invalid`. No external telemetry is sent.

## Verify or prepare the model cache

For a released package, verify its default cache without network access:

```bash
node ./node_modules/@sap-ux/mockserver-data-generator/dist/cli.js verify
```

If verification reports an incomplete component, prepare the same immutable
manifest while network access is available, then verify it again:

```bash
node ./node_modules/@sap-ux/mockserver-data-generator/dist/cli.js prepare
```

Preparation downloads only manifest-declared HTTPS artifacts and publishes
them after exact byte-size and SHA-256 verification. The normal developer does
not need either command: `npm run start-mock -- --mockgen` performs the same
preparation before Fiori starts. `--manifest` and `--cache` remain available
for controlled development, provisioning, and rollback. For unpublished
source, use the repository's local/BAS development-kit setup helper instead of
a registry `npx` command.

## Proxy or certificate failure during preparation

Default model preparation honors `HTTP_PROXY`, `HTTPS_PROXY`, and `NO_PROXY`,
including their lowercase forms. Confirm those variables in the same shell
that runs `prepare`; do not paste proxy URLs containing credentials into issue
reports or logs. Use `NO_PROXY` for an approved direct mirror when required.

A proxy or certificate error leaves no verified partial artifact. Correct the
environment or trust configuration and run `prepare` again. A local CONNECT
proxy regression covers environment routing, but the project must still run an
HTTPS proxy and certificate canary in each supported BAS environment.

## Force whole-service regeneration

For one diagnostic run, set `generatedDataCache: false`. This bypasses the
generated-row cache without deleting it or touching the separately verified
model cache. Alternatively, set `generatedDataCacheDirectory` to a new empty,
writable directory. Restore the previous option after the test if warm-cache
behavior is required.

Corrupt generated-cache entries are quarantined automatically. Do not edit the
model cache to force regeneration; model artifacts are immutable inputs and an
edited file correctly fails verification.

## Work offline

Run `prepare` once while connected, then run `verify` before entering the
offline environment. No application YAML change is required. A later
`npm run start-mock -- --mockgen` verifies and reuses the same default cache
without network access.

On first flagged use with an empty offline cache, the launcher emits
`MODEL_ACQUISITION_FAILED` and still starts Fiori with deterministic MockGen
data. The provider itself receives only cache-only state and never downloads
inside the mockserver deadline.

## Pin or roll back a model

Use the controlled `--manifest` and `--cache` command overrides to prepare and
verify the required immutable manifest. A production rollback will update the
package-owned release manifest or its approved channel. The manifest revision
and classifier/SFT fingerprints participate in the generated-data-cache key,
so changing the model cannot reuse rows generated by a different model
fingerprint.

An approved public channel and N-1 rollback mechanism do not exist yet. Until
they are released and tested, model rollback is an explicit manifest pin, not
an automatic channel operation.

## Disable the provider

Run `npm run start-mock` without `--mockgen` to use the standard mockserver's
built-in behavior for that launch. To remove the installed integration, use the
development kit's guarded `--restore` flow; a service can also set
`mockDataGenerator: false` to disable inherited provider configuration. Keep
the existing `sap-fe-mockserver` middleware and `start-mock` command; do not add
a second middleware or start command.

To retain MockGen's deterministic generation while disabling every learned
tier, set `options.mode: deterministic`. The generator does not call the
classifier or SFT runtime, reports both learned capabilities as unavailable,
and omits their fingerprints from the result. This is a local operational
control; it does not replace the still-pending model-channel T2 kill switch.

## Common degradation codes

| Code | Meaning | Action |
| --- | --- | --- |
| `MODEL_CACHE_UNAVAILABLE` | The manifest, acquisition, or verified cache could not initialize learned mode | Run offline `verify`; prepare the exact manifest if appropriate; deterministic data remains active |
| `CLASSIFIER_RUNTIME_UNAVAILABLE` | The classifier component or selected checksum-verified native runtime is unavailable | Run `verify` and check that the release manifest supports the current OS/CPU; SFT and lower tiers remain eligible |
| `SFT_RUNTIME_UNAVAILABLE` | The SFT component or selected checksum-verified native runtime is unavailable | Run `verify` and inspect the privacy-safe component/runtime status; lower tiers remain active |
| `CLASSIFIER_INFERENCE_FAILED` | One classifier inference failed | The classifier circuit stays open for the current generation epoch; correct the runtime and trigger a fresh start or reload |
| `SFT_INFERENCE_TIMEOUT` | Entity-level SFT inference exceeded its configured budget | Reduce workload or investigate the runtime; deterministic values are served |
| `SFT_INFERENCE_FAILED` | SFT execution or output validation failed | Inspect component readiness and retry in a fresh process after correction |
| `GENERATED_DATA_CACHE_UNAVAILABLE` | The generated-row cache could not be read | Check directory permissions or disable the cache for the run |
| `GENERATED_DATA_CACHE_WRITE_FAILED` | Generation succeeded but the snapshot was not cached | Serving continues; check free space and directory permissions |

If disabling the provider does not restore the application, diagnose the
standard mockserver configuration independently; that failure is outside the
optional MockGen provider path.
