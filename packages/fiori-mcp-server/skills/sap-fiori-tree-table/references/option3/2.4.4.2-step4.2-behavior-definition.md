# Step 4.2: Behavior Definition

Create 1 behavior definition. Requires Step 4.1 base views activated.

**⚠️ PREREQUISITE**: Both base views (`ZR_TravelRequest` and `ZR_TravelActivity`) must be activated before creating behavior definition.

---

## Behavior Definition (e.g., `zr_travelrequest.bdef.abdl`)

**Create with "Unmanaged" workaround** (see `prerequisites-and-concepts.md`), then replace with:

```abap
managed;
strict ( 2 );
with draft;

define behavior for ZR_TravelRequest alias TravelRequest
implementation in class zbp_r_travelrequest unique
early numbering
persistent table ztrvl_req
draft table ztrvl_req_d
lock master
total etag LocalLastChangedAt
authorization master ( none )
etag master LocalLastChangedAt
{
  create;
  update;
  delete;

  field ( readonly ) TravelRequestUUID, TravelRequestID, CreatedBy, CreatedAt, 
                     LastChangedBy, LastChangedAt, LocalLastChangedAt;
  field ( mandatory ) EmployeeName;

  association _TravelActivity { create; with draft; }

  draft action Resume;
  draft action Edit;
  draft action Activate optimized;
  draft action Discard;
  draft determine action Prepare;

  mapping for ztrvl_req
  {
    TravelRequestUUID = travel_request_uuid;
    TravelRequestID = travel_request_id;
    EmployeeName = employee_name;
    CreatedBy = created_by;
    CreatedAt = created_at;
    LastChangedBy = last_changed_by;
    LastChangedAt = last_changed_at;
    LocalLastChangedAt = local_last_changed_at;
  }
}

define behavior for ZR_TravelActivity alias TravelActivity
implementation in class zbp_r_travelactivity unique
early numbering
persistent table ztrvl_act
draft table ztrvl_act_d
lock dependent by _TravelRequest
authorization dependent by _TravelRequest
etag master LocalLastChangedAt
{
  update;
  delete;

  field ( readonly ) TravelRequestUUID, ActivityID, ParentActivityUUID;
  field ( readonly : update ) SiblingOrderNumber;
  field ( readonly : update, numbering : managed ) ActivityUUID;

  association _TravelRequest { with draft; }

  association _ParentActivity
  {
    with draft;
    link action linkParentActivity;
    unlink action unlinkParentActivity;
  }
  association _ChildActivity { with draft; }

  instance hierarchy ZI_TravelActivity_HD
  {
    managed reorder action changeNextSibling;
    field ( hierarchy-index ) SiblingOrderNumber;
    ascending association _ParentActivity;
    descending association _ChildActivity { with cascading delete; };
  }

  mapping for ztrvl_act
  {
    ActivityUUID = activity_uuid;
    TravelRequestUUID = travel_request_uuid;
    ActivityID = activity_id;
    ActivityName = activity_name;
    ParentActivityUUID = parent_activity_uuid;
    SiblingOrderNumber = sibling_order_number;
    Location = location;
    ActivityType = activity_type;
    CreatedBy = created_by;
    CreatedAt = created_at;
    LastChangedBy = last_changed_by;
    LastChangedAt = last_changed_at;
    LocalLastChangedAt = local_last_changed_at;
  }
}
```

## Critical Configuration Explained

### Root Entity Configuration

```abap
define behavior for ZR_TravelRequest alias TravelRequest
implementation in class zbp_r_travelrequest unique
early numbering
persistent table ztrvl_req
draft table ztrvl_req_d
lock master
```

**Key elements**:
- `implementation in class` - **MANDATORY**: Specifies behavior implementation class
- `early numbering` - **MANDATORY**: UUIDs generated before save (not during DB commit)
- `lock master` - Root controls locking for entire aggregate
- `persistent table` / `draft table` - Links to database tables

---

### Child Entity Configuration

```abap
define behavior for ZR_TravelActivity alias TravelActivity
implementation in class zbp_r_travelactivity unique
early numbering
persistent table ztrvl_act
draft table ztrvl_act_d
lock dependent by _TravelRequest
authorization dependent by _TravelRequest
```

**Key elements**:
- `implementation in class` - **MANDATORY**: Specifies behavior implementation class
- `early numbering` - **MANDATORY**: UUIDs generated before save
- `lock dependent by` - Lock controlled by root entity
- `authorization dependent by` - Authorization delegated to root

---

### Hierarchy Block (Critical for Tree Table)

```abap
instance hierarchy ZI_TravelActivity_HD
{
  managed reorder action changeNextSibling;        // Move items up/down
  field ( hierarchy-index ) SiblingOrderNumber;    // Field used for ordering
  ascending association _ParentActivity;           // Upward navigation
  descending association _ChildActivity { with cascading delete; };  // Downward + cascade
}
```

**Purpose**:
- `managed reorder action` - Enables drag-and-drop reordering in UI
- `hierarchy-index` - Marks field that stores sibling order
- `ascending association` - References parent (upward traversal)
- `descending association` - References children (downward traversal)
- `with cascading delete` - Deleting parent removes all children

---

### Parent Association Actions (Critical for Tree Table)

```abap
association _ParentActivity
{
  with draft;
  link action linkParentActivity;      // Assign/change parent
  unlink action unlinkParentActivity;  // Remove parent assignment
}
```

**Purpose**:
- `link action` - Enables drag-and-drop parent assignment in UI
- `unlink action` - Enables removing parent (making root node)
- `with draft` - Actions work with draft instances

## Common Errors

**Error**: "View ZR_TravelActivity not found"
- **Cause**: Step 4.1 base views not activated
- **Fix**: Activate both base views first, then create behavior

**Error**: "JCO system error" during creation
- **Cause**: Using `implementationType: "Managed"` in creation tool
- **Fix**: Use "Unmanaged" workaround (see Prerequisites guide)

**Error**: "Early numbering not declared"
- **Cause**: Missing `early numbering` statement
- **Fix**: Add to BOTH root and child behavior definitions

**Error**: "Implementation class not found"
- **Cause**: Missing `implementation in class` statement
- **Fix**: Add to BOTH root and child behavior definitions (classes auto-generated)
