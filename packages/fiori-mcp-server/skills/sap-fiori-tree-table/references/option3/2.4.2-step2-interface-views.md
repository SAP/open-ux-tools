# Step 2: Interface Views

Create 2 interface views with associations. Requires Step 1 tables activated.

## Root Interface View (e.g., `ZI_TravelRequest`)

```abap
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Travel Request - Interface View'
define root view entity ZI_TravelRequest
  as select from ztrvl_req
  association [1..*] to ZI_TravelActivity as _TravelActivity
    on $projection.TravelRequestUUID = _TravelActivity.TravelRequestUUID
{
  key travel_request_uuid as TravelRequestUUID,
      travel_request_id as TravelRequestID,
      employee_name as EmployeeName,
      // ... other fields
      
      @Semantics.user.createdBy: true
      created_by as CreatedBy,
      @Semantics.systemDateTime.createdAt: true
      created_at as CreatedAt,
      @Semantics.user.lastChangedBy: true
      last_changed_by as LastChangedBy,
      @Semantics.systemDateTime.lastChangedAt: true
      last_changed_at as LastChangedAt,
      @Semantics.systemDateTime.localInstanceLastChangedAt: true
      local_last_changed_at as LocalLastChangedAt,
      
      _TravelActivity
}
```

**Critical**: Composition `[1..*]` to child entity.

## Child Interface View (e.g., `ZI_TravelActivity`)

```abap
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Travel Activity - Interface View'
define view entity ZI_TravelActivity
  as select from ztrvl_act
  association [0..1] to ZI_TravelRequest as _TravelRequest
    on $projection.TravelRequestUUID = _TravelRequest.TravelRequestUUID
  association [0..1] to ZI_TravelActivity as _ParentActivity
    on  $projection.TravelRequestUUID  = _ParentActivity.TravelRequestUUID
    and $projection.ParentActivityUUID = _ParentActivity.ActivityUUID
  association [0..*] to ZI_TravelActivity as _ChildActivity
    on  $projection.TravelRequestUUID = _ChildActivity.TravelRequestUUID
    and $projection.ActivityUUID      = _ChildActivity.ParentActivityUUID
{
  key activity_uuid as ActivityUUID,
  key travel_request_uuid as TravelRequestUUID,
      activity_id as ActivityID,
      activity_name as ActivityName,
      parent_activity_uuid as ParentActivityUUID,
      sibling_order_number as SiblingOrderNumber,
      location as Location,
      activity_type as ActivityType,
      // ... other fields
      
      @Semantics.user.createdBy: true
      created_by as CreatedBy,
      @Semantics.systemDateTime.createdAt: true
      created_at as CreatedAt,
      @Semantics.user.lastChangedBy: true
      last_changed_by as LastChangedBy,
      @Semantics.systemDateTime.lastChangedAt: true
      last_changed_at as LastChangedAt,
      @Semantics.systemDateTime.localInstanceLastChangedAt: true
      local_last_changed_at as LocalLastChangedAt,
      
      _TravelRequest,
      _ParentActivity,
      _ChildActivity
}
```

---

## Three Critical Associations

1. **`_TravelRequest [0..1]`** - Directory association (child → root)
   - **MANDATORY for hierarchy directory filtering**
   - Without this, hierarchy cannot filter by root entity

2. **`_ParentActivity [0..1]`** - Self-reference to parent (upward navigation)
   - Used in hierarchy's `child to parent association`
   - Enables traversing up the hierarchy

3. **`_ChildActivity [0..*]`** - Self-reference to children (downward navigation)
   - Used in behavior's `descending association`
   - Enables traversing down the hierarchy

---

## Key Points

- Root has composition `[1..*]` to child
- Child has `association [0..1]` to root (directory) - **REQUIRED for hierarchy filtering**
- Child has two self-associations: `[0..1]` parent (upward), `[0..*]` children (downward)
- All associations must be exposed in select list
