# Step 3: Hierarchy Definition

Create 1 hierarchy definition. Requires Step 2 interface views activated.

⚠️ **No "Create Hierarchy" tool** - Create Data Definition first, then replace with hierarchy syntax.

## Hierarchy View (e.g., `ZI_TravelActivity_HD`)

```abap
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Travel Activity Hierarchy Definition'
define hierarchy ZI_TravelActivity_HD
  with parameters
    P_TravelRequestUUID : sysuuid_x16
  as parent child hierarchy(
    source ZI_TravelActivity
    child to parent association _ParentActivity
    directory _TravelRequest filter by
      TravelRequestUUID = $parameters.P_TravelRequestUUID
    start where
      ParentActivityUUID is initial
    siblings order by
      SiblingOrderNumber ascending
  )
{
  key TravelRequestUUID,
  key ActivityUUID,
      ParentActivityUUID,
      SiblingOrderNumber
}
```

---

## Critical Elements Explained

### 1. `with parameters`
```abap
with parameters
  P_TravelRequestUUID : sysuuid_x16
```
- Accepts directory/root UUID to filter hierarchy
- Isolates hierarchies by root entity
- Prevents mixing data from different roots

### 2. `child to parent association`
```abap
child to parent association _ParentActivity
```
- Upward link to parent node
- References the `_ParentActivity` association from interface view
- Enables traversing up the hierarchy

### 3. `directory` filter
```abap
directory _TravelRequest filter by
  TravelRequestUUID = $parameters.P_TravelRequestUUID
```
- Filters hierarchy by root entity (directory)
- Uses the `_TravelRequest` association from child interface view
- Multi-line format required (do not inline)
- **MANDATORY**: Without this, hierarchy cannot isolate by root

### 4. `start where`
```abap
start where
  ParentActivityUUID is initial
```
- Identifies root nodes of the hierarchy
- Root nodes have no parent (parent UUID is empty/initial)
- Multi-line format required

### 5. `siblings order by`
```abap
siblings order by
  SiblingOrderNumber ascending
```
- Defines ordering of nodes at the same level
- Ensures proper tree rendering sequence
- Multi-line format required

---

## Common Errors

**Error**: "Association _TravelRequest not found"
- **Cause**: Child interface view missing directory association
- **Fix**: Ensure `ZI_TravelActivity` has `association [0..1] to ZI_TravelRequest`

**Error**: "Primary keys do not match"
- **Cause**: Child active table missing composite key
- **Fix**: Ensure child table has both `activity_uuid` and `travel_request_uuid` as keys
