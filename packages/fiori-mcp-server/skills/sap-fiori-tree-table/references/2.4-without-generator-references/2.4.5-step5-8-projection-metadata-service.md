# Steps 5-8: Projection Layer, Metadata & Service

## Step 5: Projection Views

Create 2 projection views. Requires Step 4 behavior activated.

### Root Projection (e.g., `ZC_TravelRequest`)

```abap
@EndUserText.label: 'Travel Request - Projection View'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@Metadata.allowExtensions: true
define root view entity ZC_TravelRequest
  provider contract transactional_query
  as projection on ZR_TravelRequest
{
  key TravelRequestUUID,
      TravelRequestID,
      EmployeeName,
      // ... other fields
      CreatedBy,
      CreatedAt,
      LastChangedBy,
      LastChangedAt,
      LocalLastChangedAt,
      
      _TravelActivity : redirected to composition child ZC_TravelActivity
}
```

### Child Projection (e.g., `ZC_TravelActivity`) - **CRITICAL Annotation**

```abap
@EndUserText.label: 'Travel Activity - Projection View with Hierarchy'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@Metadata.allowExtensions: true
@OData.hierarchy.recursiveHierarchy: [{ entity.name: 'ZI_TravelActivity_HD' }]
define view entity ZC_TravelActivity
  as projection on ZR_TravelActivity
{
  key ActivityUUID,
  key TravelRequestUUID,
      ActivityID,
      ActivityName,
      ParentActivityUUID,
      SiblingOrderNumber,
      Location,
      ActivityType,
      // ... other fields
      CreatedBy,
      CreatedAt,
      LastChangedBy,
      LastChangedAt,
      LocalLastChangedAt,
      
      _TravelRequest : redirected to parent ZC_TravelRequest,
      _ParentActivity : redirected to ZC_TravelActivity,
      _ChildActivity : redirected to ZC_TravelActivity
}
```

**Critical**: `@OData.hierarchy.recursiveHierarchy` is MANDATORY for tree table rendering.

## Step 6: Projection Behavior Definition

Create 1 projection behavior definition. Requires Step 5 projections activated.

### Projection Behavior (e.g., `zc_travelrequest.bdef.abdl`)

```abap
projection;
strict ( 2 );
use draft;

define behavior for ZC_TravelRequest alias TravelRequest
use etag
{
  use create;
  use update;
  use delete;

  use action Resume;
  use action Edit;
  use action Activate;
  use action Discard;
  use action Prepare;

  use association _TravelActivity { create; with draft; }
}

define behavior for ZC_TravelActivity alias TravelActivity
use etag
{
  use update;
  use delete;

  use action changeNextSibling;

  use association _TravelRequest { with draft; }
  use association _ParentActivity { 
    with draft; 
    link action linkParentActivity; 
    unlink action unlinkParentActivity; 
  }
  use association _ChildActivity { with draft; }
}
```

**Critical**: `use etag` on BOTH entities for proper draft handling.

**Validation**: Activate projection behavior.

## Step 7: Metadata Extensions (UI Annotations)

Create 2 metadata extensions. Requires Step 6 projection behavior activated.

### Root Metadata Extension (e.g., `zc_travelrequest.ddlx.acds`)

**CRITICAL**: Must include `#LINEITEM_REFERENCE` facet for tree table display.

```abap
@Metadata.layer: #CORE
annotate entity ZC_TravelRequest with
{
  @UI.facet: [
    {
      id: 'TravelRequestInfo',
      purpose: #STANDARD,
      type: #IDENTIFICATION_REFERENCE,
      label: 'Travel Request Details',
      position: 10
    },
    {
      id: 'TravelActivities',
      purpose: #STANDARD,
      type: #LINEITEM_REFERENCE,
      label: 'Travel Activities',
      position: 20,
      targetElement: '_TravelActivity'
    }
  ]
  
  @UI.hidden: true
  TravelRequestUUID;

  @UI: {
    lineItem: [{ position: 10, importance: #HIGH }],
    identification: [{ position: 10 }]
  }
  TravelRequestID;
  
  @UI: {
    lineItem: [{ position: 20, importance: #HIGH }],
    identification: [{ position: 20 }]
  }
  EmployeeName;
  
  @UI.hidden: true
  CreatedBy;
  @UI.hidden: true
  CreatedAt;
  @UI.hidden: true
  LastChangedBy;
  @UI.hidden: true
  LastChangedAt;
  @UI.hidden: true
  LocalLastChangedAt;
}
```

**Critical Facets**:
- **Facet 1**: Root entity header fields
- **Facet 2**: **MANDATORY** - displays child tree table in Object Page
