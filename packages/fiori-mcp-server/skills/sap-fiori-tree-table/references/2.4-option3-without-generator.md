## Quick Step Overview

| Step | Objects | Key Requirements |
|------|---------|------------------|
| **1** | 4 Tables | Draft fields lowercase, no underscores; child draft has composite key |
| **2** | 2 Interface Views | Child needs 3 associations: directory, parent, children |
| **3** | 1 Hierarchy Definition | Must have parameters and directory filter |
| **4.1** | 2 Base Views | Transactional layer; maintain same 3 associations as interface views |
| **4.2** | 1 Behavior Definition | Both entities need `early numbering` and `implementation in class` |
| **5** | 2 Projection Views | Child needs `@OData.hierarchy.recursiveHierarchy` annotation |
| **6** | 1 Projection Behavior | Both entities need `use etag` |
| **7** | 2 Metadata Extensions | Root needs `#LINEITEM_REFERENCE` facet; child needs `presentationVariant` |
| **8** | 1 Service Definition + Binding | Expose both entities, then publish |

## Critical Success Factors

### 1. Sequential Execution
- Activate ALL objects in Step N before starting Step N+1
- Dependencies will cause failures if order is not followed

### 2. Field Naming (Draft Tables)
- **Active table**: snake_case (e.g., `travel_request_uuid`)
- **Draft table**: lowercase, no separators (e.g., `travelrequestuuid`)

### 3. Composite Keys
- Child active table: `[client, child_uuid, root_uuid]`
- Child draft table: `[mandt, child_uuid, root_uuid]`

### 4. Three Critical Associations (Child Entity)
```abap
association [0..1] to ZI_TravelRequest as _TravelRequest    // Directory
association [0..1] to ZI_TravelActivity as _ParentActivity  // Parent
association [0..*] to ZI_TravelActivity as _ChildActivity   // Children
```

### 5. Mandatory Annotations
- Child projection: `@OData.hierarchy.recursiveHierarchy`
- Root metadata: `#LINEITEM_REFERENCE` facet
- Child metadata: `presentationVariant` sorted by `SiblingOrderNumber`

## Communication Pattern

**For each step:**
1. Create objects for that step only
2. Activate all objects
3. Show user what was created
4. Ask: "Step X completed. Ready for Step Y?"
5. Wait for confirmation
6. Move to next step

**On errors:**
- STOP immediately
- Show error details
- Ask how to proceed
- Do NOT continue to next step

---

## Implementation Strategy

**Phase 1: Planning**
1. Create implementation plan document
2. List all objects with naming conventions
3. Specify fields for tables and views
4. Present to user and wait for approval

**Phase 2: Execution**
1. Execute steps 1-8 sequentially
2. Pause after each step for user confirmation
3. Handle errors before proceeding

**Phase 3: Testing**
1. Publish service binding
2. Preview in Fiori Elements
3. Test hierarchical operations
4. Document results
